# /arch — 구조 설계 → 스캔 → 수정

명령 앞에는 항상 `"{{PYTHON}}" -m audit_kit` 을 붙인다 (아래에서는 `AK` 로 표기).

## 1. 설계 초안

- `architecture.toml` 이 없으면 `AK arch init` 으로 초안을 만든다 (폴더 이름으로 계층 추정, 외부 라이브러리 사용 위치 수집).
- `architecture.toml` 과 `ARCHITECTURE.md` 를 읽는다.

## 2. 설계 확정 (사용자와 함께)

초안을 계층 표로 보여 주고, **사람이 정해야 하는 것만** 짧게 묻는다:
- 미배정 모듈(`!! 미배정`)이 어느 계층인지, **제품도 보조 코드도 아닌 폴더**(temp 등)는 역할 지정/삭제/제외 중 무엇인지
- `[support]` 분류가 맞는지 (tests / scripts / plugins / migrations).
  제품 코드가 '플러그인'을 임포트하고 있으면, 그 폴더가 사실상 제품 부품인지 물어서
  맞으면 제품 패키지로 승격(계층에 배정), 아니면 필요한 코드를 제품 쪽으로 옮기는 수정 대상으로 둔다
- 도메인 규칙: 예) ezdxf 도면 계산 로직이 FastAPI·AutoCAD 플러그인을 몰라야 하는가 → `[[forbidden]]`
- 서로 독립이어야 하는 모듈 (플러그인끼리 등) → `[[independent]]`
- 외부 라이브러리 위치 제한 (fastapi 는 interface 만, ezdxf 는 도면 모듈만 등) → `[[external]]`
- 프로젝트 유형(`types`)과 계층별 책임·금지(`responsibility`, `must_not`)가 맞는지
- **공통 관심사 위치** `[concerns]` (설정·로깅·DB·COM·HTTP): 초안의 `# !!` 메모(전용 모듈이 여러 개, 권장 계층 밖)를 보여 주고
  어디로 모을지 정한다. 전용 모듈이 없으면 만들 위치를 정한다

답을 반영해 `architecture.toml` 을 고치고 `AK arch doc` 으로 문서를 갱신한다.
설계를 코드에 맞추려고 규칙을 느슨하게 만들지 않는다. 느슨하게 할 때는 사용자 동의를 받는다.

## 3. 스캔

`AK arch check` — 위반 목록을 규칙별로 요약해 보여 준다.

## 4. 자동 수정

1. `AK arch fix` (미리보기) — 어떤 수정을 할지와 diff 를 사용자에게 요약한다.
   - reexport: 상위 모듈을 거쳐 가져오던 이름을 원 정의 위치에서 직접 임포트
   - unused: 안 쓰는 위반 임포트 제거
   - type_only: 타입 힌트 전용 임포트를 `if TYPE_CHECKING:` 으로
   - move: 상위 계층 함수/클래스/상수를 쓰는 하위 모듈로 이동 (+ 다른 사용처 임포트 갱신)
2. 사용자가 동의하면 `AK arch fix --apply --verify`
   - 커밋 안 된 변경이 있다고 거부하면 먼저 커밋하자고 제안한다 (`--force` 는 사용자가 원할 때만).
   - 적용 후 문제가 있으면 `AK arch undo` 로 되돌린다.
3. `--allow-lazy` (함수 안 지연 임포트로 순환 끊기)는 임시 처방이다. 사용자 동의 없이 쓰지 않는다.

## 5. 남은 위반 수동 수정

`audit-reports/arch-fix_*/arch-fix.md` 의 "남은 위반" 을 **한 건씩** 처리하고, 매 건마다 `AK arch check` 로 확인한다.

| 규칙 | 수정 방법 |
|---|---|
| 계층 역방향 (이동 불가 사유: 같은 모듈의 다른 함수·상태에 의존) | 의존 묶음을 함께 하위 계층 새 모듈로 추출. 상태(레지스트리 등)가 걸리면 상위 계층이 하위에 함수/값을 **인자로 넘기도록** 바꾼다(의존성 역전) |
| 순환 임포트 | 양쪽이 공유하는 부분을 하위 모듈로 추출 |
| 외부 라이브러리 위치 | 허용된 계층에 래퍼 함수를 두고, 나머지는 평범한 값(dict/dataclass)만 주고받게 |
| 진입점 임포트 | main 에 있는 공용 객체(설정·DB 엔진 등)를 infra 로 옮기고 main 은 조립만 |
| 금지·독립 규칙 | 공통 부분 추출 또는 인터페이스(Protocol)를 하위 계층에 정의 |
| 제품 → 보조 코드 | 필요한 코드를 제품 패키지로 옮기고 보조 코드가 그것을 임포트. 폴더 자체가 제품 부품이면 설계에서 승격(사용자 확인) |
| 비공개(_) 함수 사용 | 제품에 공개 함수를 추가(기존 _함수를 감싸거나 이름 변경 + 재수출)하고 스크립트가 그것을 쓰게 |
| 미배정·설계 불일치 | 코드가 아니라 architecture.toml / [tool.audit-kit] support·exclude_paths 를 고친다 (사용자 확인) |

원칙:
- 동작을 바꾸지 않는다. 공개 이름이 바뀌면 원래 위치에 재수출(`from new import name`)을 남긴다.
- 파일을 옮기면 모든 사용처 임포트를 고친다 (저장 시 hook 이 설계 위반·타입 오류를 알려 준다).
- 끝나면 테스트를 돌린다.

## 6. 마무리

- `AK arch check` 위반 0건(또는 사용자가 수용한 것만 남음) 확인
- `AK arch doc` 로 ARCHITECTURE.md 갱신
- 사용자에게 "위반 N → M건, 자동 수정 X건, 수동 수정 Y건" 을 보고하고 `/audit` 로 전체 감사를 제안한다.
