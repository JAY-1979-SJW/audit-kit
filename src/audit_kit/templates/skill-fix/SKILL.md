# /audit-fix — 감사 결과 수정

명령 앞에는 항상 `"{{PYTHON}}" -m audit_kit` 을 붙인다 (아래에서는 `AK`).
명령은 하나씩 실행한다.

## 0. 사전 확인

- 프로젝트 CLAUDE.md 의 **브랜치 정책·보호 파일 규칙**을 먼저 읽는다. 보호 파일은
  `pyproject.toml` 의 `[tool.audit-kit] protected_paths` 에 glob 으로 넣어 두면 계획에서 🔒 로 표시된다.
- 최근 감사가 없거나 코드가 바뀌었으면 `AK run` 을 먼저 실행한다.
- 커밋 안 된 변경이 있으면 사용자에게 알리고 멈춘다.

## 1. 계획 → 사용자 승인

1. `AK fix plan` (기본: 치명만). 범위 조절: `--rules F821,call-arg` / `--files "mcp_server/*"` / `--include-review` / `--limit 10`
2. 계획을 표로 요약해서 보여 주고 **범위를 확인받는다** (AskUserQuestion):
   - 전부 / 일부 규칙만 / 먼저 N건만
   - 환경 문제로 보이는 항목(패키지 미설치로 인한 테스트 수집 실패, 테스트 데이터 파일 누락)은 미리 "건너뜀 예정"으로 표시
3. 승인되면 `AK fix start` (브랜치 `audit-fix/날짜` 생성 + 테스트 기준선 기록).
   프로젝트 브랜치 규칙이 있으면 `--branch feature/...` 로 이름을 맞춘다.

## 2. 한 건씩 수정 (반복)

각 항목(`AK fix status` 의 pending)에 대해:

1. `fix-plan.md` 의 해당 항목(문제·근거·수정 방향)을 읽고, **파일을 열어 주변 코드를 확인**한다.
2. **최소 범위로 수정**한다.
   - 빠진 import 는 `git log -S <이름>` 으로 원래 위치를 찾아 복구한다 (새로 만들지 않는다).
   - 동작이 바뀌는 수정(함수 시그니처 변경, 기능 삭제 여부 판단)은 사용자에게 먼저 묻는다.
   - 테스트 기대값은 근거 없이 바꾸지 않는다.
   - 🔒 보호 항목은 사용자 승인 없이 손대지 않는다.
3. `AK fix check <ID>` — 통과하면 `AK fix done <ID> --trailer "Co-Authored-By: Claude <noreply@anthropic.com>"`
4. 실패하면 원인을 보고 한 번 더 시도한다. **2번 실패하면** 변경을 되돌리고(`git checkout -- <파일>`)
   `AK fix skip <ID> --reason "<이유>"` 로 넘어간다.
5. 환경 문제(패키지 미설치, 데이터 파일 누락, 외부 서비스 필요)는 고치지 말고 skip 하고 사유를 남긴다.

한 수정으로 여러 항목이 함께 고쳐졌으면 각각 `fix check` 로 확인하고 `AK fix done F001 F002` 처럼 한 커밋으로 묶는다.
이미 커밋한 뒤라면 `fix done <ID>` 가 앞 커밋에 포함된 것으로 기록한다.

## 3. 마무리

1. `AK fix report` — 전체 테스트를 기준선과 비교. **새 실패가 있으면** 원인 커밋을 찾아 `git revert` 하고 해당 항목을 skip 처리.
2. 사용자에게 보고:
   - 완료 N / 건너뜀 N (사유별) / 새 테스트 실패 0
   - 브랜치 이름, 커밋 목록, 보고서 경로
3. push·PR 은 **사용자가 원할 때만**. PR 본문은 `fix-report.md` 내용을 쓴다.
4. `AK fix end` 로 세션 기록을 정리한다 (브랜치·커밋은 남음).
