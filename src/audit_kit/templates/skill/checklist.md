# AI 설계 리뷰 체크리스트

도구(1~8단계)가 못 잡는 구조 문제를 판정할 때 쓰는 기준. 프로젝트에 맞게 항목을 추가·수정해도 된다.

## 등급 기준

| 등급 | 정의 | 조치 |
|---|---|---|
| 치명 | 지금 당장 데이터 손실·보안 사고·서비스 중단으로 이어질 수 있음 | 즉시 수정 |
| 개선 | 동작하지만 불안정하거나 유지보수를 어렵게 함 | 우선순위 큐 |
| 무시 | 실제 문제 아님(오탐) 또는 영향 미미 | 기록만 |

## A. DB 세션 수명주기 (SQLAlchemy)
- [ ] 세션이 요청 단위 의존성(`Depends(get_db)` 등) 또는 `with Session(...)` 블록으로만 생성되는가?
      함수 안에서 `SessionLocal()`을 직접 만들고 닫지 않으면 → **개선**, 쓰기 작업인데 commit이 없으면 → **치명**
- [ ] 쓰기 작업(add/delete/update) 후 commit, 예외 시 rollback 경로가 있는가? 없으면 → **치명**
- [ ] 모듈 전역 세션 인스턴스(요청 간 공유)가 있는가? → **치명**
- [ ] 서비스 함수가 세션을 인자로 받는가(테스트 가능성)? 아니면 → **개선**

## B. 계층 분리
- [ ] 라우터(api/routers/endpoints)는 요청 검증 → 서비스 호출 → 응답 변환만 하는가?
      계산·반복·DB 직접 조회가 있으면 → **개선** (services/로 이동 제안)
- [ ] 하위 계층(models/core/db)이 상위 계층(api/services)을 임포트하는가? → **개선**
      그로 인해 순환 임포트가 실제 ImportError를 낸다면 → **치명**
- [ ] (MyProject) AutoCAD 플러그인/UI 코드와 ezdxf 도면 계산 로직이 분리되어 있는가?
      계산 모듈이 플러그인·UI·FastAPI를 임포트하면 → **개선**

## C. SQL 작성
- [ ] SQL을 f-string / `+` / `%` / `.format()`으로 조합하는가?
      외부 입력(요청 파라미터·파일 내용)이 들어가면 → **치명**, 상수/화이트리스트 값만이면 → **무시**(사유 기록)
- [ ] `text()` 사용 시 바인드 파라미터(`:name`)를 쓰는가?

## D. 오류 처리·자원
- [ ] `except Exception: pass` 류로 오류를 삼키는가? 데이터 처리 경로면 → **개선**
- [ ] 파일·DXF 문서·DB 연결이 `with`로 닫히는가?

## E. 오탐 판정 요령
- FastAPI 라우터·의존성, SQLAlchemy 모델 속성, Pydantic validator는 프레임워크가 호출하므로 vulture 오탐 가능성이 높다.
- 도메인 계산(물량 산출, 도면 파싱)은 원래 복잡할 수 있다 — radon 등급만으로 치명 판정하지 않는다.
