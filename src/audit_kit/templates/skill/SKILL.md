# /audit — 표준 코드 감사

## 0. 구조 설계 먼저

프로젝트 루트에 `architecture.toml` 이 없으면, 감사 전에 `/arch` 로 구조(계층·임포트 규칙)를 설계하고
위반을 정리하자고 사용자에게 제안한다. 설계 파일이 있으면 3단계가 설계 기준 검사로 바뀐다.

## 1. 도구 감사 실행 (1~8단계, 결정론적)

```
"{{PYTHON}}" -m audit_kit run
```

- 인자 `$ARGUMENTS`에 `--no-tests`, `--only ruff,mypy` 등이 있으면 그대로 붙인다.
- 끝나면 `audit-reports/LATEST.txt`에 적힌 폴더의 `report.md`, `ai-review.md`를 읽는다.
- 도구 상태가 "오류"면 원인(설정 누락, 미설치 등)을 먼저 사용자에게 알린다.

## 2. AI 설계 리뷰 (9단계)

`checklist.md`(이 스킬 폴더)의 항목을 기준으로 판정한다. 범위는 넓히지 않는다:

1. `ai-review.md`의 **휴리스틱 후보** 전부 — 해당 파일·줄을 직접 열어 확인
2. **문제가 몰린 파일** 상위 5개
3. **라우터 파일** 목록 — 비즈니스 로직 혼입 여부
4. import-linter 위반(AI 리뷰 필요 등급) — 설계상 허용 가능한지

각 항목마다 치명 / 개선 / 무시 중 하나로 판정하고, 판정 이유를 코드 근거와 함께 한 줄로 적는다.
도구가 이미 확정한 등급(치명·개선·무시)은 다시 판정하지 않는다.
휴리스틱에 안 걸렸지만 읽다가 발견한 체크리스트 위반도 추가한다.

## 3. 리포트 완성

같은 폴더의 `report.md` 끝에 아래 형식으로 추가한다(기존 내용은 수정하지 않음):

```
## AI 리뷰 판정 (9단계)
### 치명
1. [DB] app/services/x.py:52 — 세션 commit 없이 함수 종료, 데이터 유실 위험
   근거: SQLAlchemy Session Basics — 트랜잭션은 명시적 commit/rollback 필요
### 개선
...
### 무시
1. [구조] app/api/health.py:10 — 라우터 휴리스틱 오탐: 단순 상태 조회
```

## 4. 사용자 보고

- 치명 건수와 목록(파일:줄 — 한 줄 설명)을 먼저, 개선은 상위 5건만 요약한다.
- 리포트 경로를 알려준다.
- **코드 수정은 사용자가 요청할 때만 한다.** 수정 요청 시 `/audit-fix` 절차(브랜치 → 건별 재검사·커밋)를 따른다.
