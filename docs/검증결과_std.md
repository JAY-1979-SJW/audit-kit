| 방법 | 결과 |
|---|---|
| ① 실제 코드 표본 검토 (정밀도) | 956개 파일에서 오탐 원인 5가지를 찾아 고침. 직접 구현 조항 대부분이 표본에서 진짜 위반으로 확인됨 (아래 표) |
| ② 결함 심기 (재현율) | 실제 파일 25개 × 결함 21종 = 525건 **모두 검출 (100%)**, 파일 단위 조항 2개도 검출 |
| ③ 변형 패턴 시험 | 검사기별 정상·위반 변형 시험 지속 확장: 결함 3종(오탐 2, 미탐 3) 발견·수정. 현재 test_std_variants.py 64개 통과 |

## ① 정밀도: 실제 코드 956개 파일 (5개 프로젝트, 표본 검토)

직접 구현한 조항은 오탐 위험이 커서 조항마다 표본을 뽑아 코드 문맥으로 진짜 위반인지 판정했다. ruff 규칙으로 매핑한 조항은 ruff 의 판정을 따른다.

| 조항 | 표본 판정 | 조치 |
|---|---|---|
| DUP-02 본문이 같은 함수 | 5/5 진짜 | 유지. 변수 이름만 바꾼 복사도 찾도록 확장 |
| DUP-03 복사본 파일명 | `bridge_v2.py` 는 버전 관리되는 API 파일일 수 있음 | `_v2`·`_final` 은 참고 등급으로 낮춤 |
| STD-11 루트의 test 스크립트 | 2/2 진짜 | 유지 |
| STD-02 하드코딩 절대경로 | 8/8 진짜 (`/home/ubuntu/...`, `C:\Users\...`) | 유지 |
| ERR-03 `shell=True` | 4/4 진짜 | 유지 |
| ERR-01 없는 import | 프로젝트 안 다른 폴더에 있는 모듈을 치명으로 오판. `collectors` 등 프로젝트 어디에도 없는 것은 진짜 깨진 import | 프로젝트 전체에서 이름을 찾도록 수정 (치명 97 → 79) |
| EFF-03 반복 안 I/O | **표본 12/12 정상 사용**: 파일마다 다른 경로, 재시도·폴링, 체크포인트 저장, 앱 후보 순회 | 같은 대상을 반복해 여는 경우로 좁힘 (189 → 5). 남은 5건도 정상 → **참고 등급** |
| EFF-02 반복 안 list `in` | 순서 유지 중복 제거, 작은 목록이 대부분 | 순서 유지 패턴 제외, **참고 등급** (33 → 23) |
| EFF-04 read_only | 저장하는 편집용 워크북도 잡음 | 저장하는 파일 제외 (6 → 4, 나머지는 읽기 전용이라 유효) |
| EFF-05 셀 단위 접근 | 값·스타일 쓰기(범위 스타일 API 없음)가 대부분 | 읽기만 검사 (35 → 9) |
| EFF-06 COM 정리 | 실행 중인 AutoCAD 에 붙는 코드는 Quit 하면 사용자 세션이 닫힘 | Excel·Word 등 Office 앱만 대상. 기준서 CLAUDE.md 도 정정 |
| STD-09 비밀값 | ruff S105 가 `PASS = "PASS"` 같은 것을 오탐 (0/2 진짜) | 치명 → 개선 등급 |

**해석**: 반복 안 I/O(EFF-03) 처럼 "규칙 문장은 그럴듯하지만 실제 코드에서는 대부분 정상 사용"인 조항이 있었다. 이런 조항은 자동 검사를 좁히고 참고 등급으로 두었다. 진짜 위반이 확인된 것은 DUP-02·STD-02·STD-11·ERR-03·ERR-01(깨진 import) 이다.

## ② 재현율: 결함 심기

실제 파일 25개(20~500줄) 뒤에 조항별 결함 21종을 자동으로 붙이고, 심은 위치에서 그 조항이 보고되는지 확인.

| 결과 | |
|---|---|
| 심은 결함 | 525개 (STD-01·02·03·04·05·06·07·08·09·10, DUP-01·02, EFF-01·02·03·04·05·06, ERR-01·03, STD-02 pathlib 변형) |
| 검출 | 525/525 (100%) |
| 파일 단위 | STD-11(루트 test 스크립트), DUP-03(`report_old.py`) 검출 |
| 첫 측정 | DUP-02 가 4% — 검사기 결함이 아니라 25개가 같은 본문이라 하나의 그룹으로 보고된 측정 방식 문제. 변이마다 본문을 다르게 해서 100% |

**한계**: 결함을 검사기와 같은 사람(AI)이 만들었으므로 낙관적이다. 다른 모양은 ③ 변형 시험이 따로 본다. ERR-02(없는 속성)는 mypy 가 필요해 이 측정에서 제외했고 tests/test_std.py 가 별도로 확인한다.

## ③ 변형 패턴 시험에서 찾은 결함

| 결함 | 종류 | 수정 |
|---|---|---|
| 반복문 안에서 함수를 정의만 해도 그 본문을 반복 실행으로 봄 | 오탐 | 중첩 정의 안쪽은 들어가지 않음 |
| 다른 함수의 같은 이름 list 를 같은 스코프로 봄 | 오탐 | 위와 같은 원인 |
| `import requests as r`, `from requests import get` 별칭을 놓침 | 미탐 | 별칭 추적 |
| 모듈 최상위의 COM 호출을 검사하지 않음 | 미탐 | 모듈도 검사 |
| 변수 이름만 바꾼 복사 함수를 놓침 | 미탐 | 지역 변수 이름 정규화 |

## 알려진 한계

- 정적 검사라 데이터 크기·실행 빈도에 따른 성능은 판단하지 못한다 (EFF-02·03·04·05 는 참고 등급).
- HTTP 요청은 재시도·페이지 반복이 정상이라 EFF-03 에서 제외했다.
- ERR-01 은 검사를 실행하는 파이썬 환경 기준이다. 대상 프로젝트의 venv 에서 실행해야 정확하다.
- 정밀도 표본은 5개 프로젝트, 조항당 2~12건이라 통계적 결론은 아니다. 발견이 적은 조항은 전수를 봤다.
- 표본 판정은 AI 가 코드 문맥을 보고 했다. 사람이 일부를 다시 확인하면 더 확실하다.
- ruff 로 매핑한 조항(STD-01·03~08·10, DUP-01, EFF-01)의 정밀도는 ruff 를 따르며 별도로 표본 검토하지 않았다.
